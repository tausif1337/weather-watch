What we're building

Weather Watch — search any city, see the current conditions.

  • 🔍 Search a city by name
  • 🌡️ Current weather: temperature, condition, humidity, wind
  • ⏳ Loading line while the request is in flight
  • ⚠️ Error message for a bad city name or a network failure
  • 💾 Cached results — searching a city twice costs one request
  • ✨ Bonus: geolocation, °C/°F toggle, 5-day forecast

API Service Module

TAUSIF

api/weatherApi.js — the request

const BASE_URL = 'https://api.openweathermap.org/data/2.5/weather'
const API_KEY = import.meta.env.VITE_WEATHER_API_KEY

export async function getWeather(city) {
  // units=metric → Celsius, wind in m/s. encodeURIComponent handles "New York".
  const url = `${BASE_URL}?q=${encodeURIComponent(city)}&units=metric&appid=${API_KEY}`
  const response = await fetch(url)

  // fetch does NOT throw on 404/401 — we must check ok ourselves.
  if (!response.ok) {
    if (response.status === 404) throw new Error('City not found. Check the spelling.')
    throw new Error('Could not fetch weather. Try again.')
  }
Translate HTTP status into friendly errors here, so components stay simple.

api/weatherApi.js — shape the response

  const data = await response.json()

  // Return only the fields we need, in a friendly shape.
  return {
    city: data.name,
    temperature: Math.round(data.main.temp),
    condition: data.weather[0].main,
    humidity: data.main.humidity,
    windSpeed: Math.round(data.wind.speed * 3.6),   // m/s → km/h
  }
}
The raw response nests everything (main.temp, weather[0].main, wind.speed). Normalise once here and no component ever learns the API's shape.

main.jsx — the provider

import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

// One QueryClient for the whole app. It stores the cache React Query uses.
const queryClient = new QueryClient()

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </React.StrictMode>,
)
Forget the provider and every useQuery throws "No QueryClient set".

TAUSIF

hooks/useWeather.js

import { useQuery } from '@tanstack/react-query'
import { getWeather } from '../api/weatherApi'

// Components call this and get { data, isLoading, isError, error }.
export function useWeather(city) {
  return useQuery({
    queryKey: ['weather', city],       // cache identity, per city
    queryFn: () => getWeather(city),   // what actually fetches
    enabled: !!city,                   // no city → no request
    retry: false,                      // don't retry a 404 forever
  })
}
21
TAUSIF

The four options that matter

  • queryKey — the cache address. Same key = same cached data.
  • queryFn — the async function; it must throw on failure.
  • enabled — !!city turns '' into false, so we don't fetch on an empty search.
  • retry — false, because "city not found" will never succeed on retry.
Anything in the key that changes triggers a refetch. That's how the °C/°F toggle works later.
22
TAUSIF

What the hook hands back

const { data, isLoading, isError, error } = useWeather(city)
  • No useState for loading or error — React Query tracks both.
  • No try / catch / finally in the component.
  • No useEffect — the hook fetches when the key changes.
  • Re-searching a city you already looked up is instant: it's cached.

State design

One piece of state in App covers the whole flow:

export default function App() {
  // The city we are currently showing weather for.
  const [city, setCity] = useState('')

  // Ask React Query for this city's weather.
  const { data, isLoading, isError, error } = useWeather(city)
}
Server state (the weather) belongs to React Query. UI state (the searched city) belongs to useState. Never copy one into the other.

Controlled search form

export function SearchBar({ onSearch }) {
  const [text, setText] = useState('')      // whatever the user is typing

  function handleSubmit(event) {
    event.preventDefault()                  // stop the page from reloading
    const city = text.trim()
    if (!city) return                       // ignore empty searches
    onSearch(city)                          // hand the city up to App
  }
  return (
    <form onSubmit={handleSubmit} className="flex gap-2">
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <button type="submit">Search</button>
    </form>
  )
}

App.jsx — render the right state

<div className="min-h-screen bg-blue-50 flex justify-center p-4">
  <div className="w-full max-w-md mt-16 space-y-4">
    <h1 className="text-center text-3xl font-bold text-blue-600">Weather Watch</h1>

    {/* On submit, save the city → triggers the query. */}

    {isLoading && <p className="text-center text-gray-500">Loading...</p>}
    {isError && <p className="text-center text-red-500">{error.message}</p>}
    {data && <WeatherCard data={data} />}
  </div>
</div>
Mutually exclusive branches: loading or error or data. Before the first search, enabled: false keeps all three quiet — you just see the form.

WeatherCard.jsx

// Pure presentation: no state, no fetch.
// data → { city, temperature, condition, humidity, windSpeed }
export function WeatherCard({ data }) {
  return (
    <div className="rounded-2xl bg-white p-6 shadow-md">
      <h2 className="text-2xl font-bold text-gray-800">{data.city}</h2>
      <p className="text-gray-500">{data.condition}</p>

      <p className="my-4 text-5xl font-bold text-blue-500">{data.temperature}&deg;C</p>

      <div className="flex justify-between text-gray-600">
        <span>Humidity: {data.humidity}%</span>
        <span>Wind: {data.windSpeed} km/h</span>
      </div>
    </div>
  )
}

Tailwind styling notes

  • The card is four utilities: rounded-2xl bg-white p-6 shadow-md.

Unit toggle (°C / °F)

const [unit, setUnit] = useState('metric')   // 'metric' | 'imperial'

<button onClick={() => setUnit((u) => (u === 'metric' ? 'imperial' : 'metric'))}>
  {unit === 'metric' ? '°C' : '°F'}
</button>

// hooks/useWeather.js — unit becomes part of the cache identity
queryKey: ['weather', city, unit],
queryFn: () => getWeather(city, unit),
Add unit to the queryKey and React Query refetches on its own — and keeps °C and °F cached separately.
